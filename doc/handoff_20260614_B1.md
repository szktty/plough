## B1 の作業内容

### ゴール
`pubspec.yaml` から `flame` 依存を外す。flame はゲームエンジン一式で、**線分交差計算の
ためだけ**に使われている(`lib/src/graph_view/shape.dart` のみ)。~50 行の自前幾何コードで
置換する。pub 品質(依存の軽さ・web 安全性)に直結。

### flame の使用箇所(`lib/src/graph_view/shape.dart` の 3 箇所)
1. `GraphLine.flameLineSegment`(31-32): `LineSegment(Vector2, Vector2)` に変換。
2. `GraphCircle.getLineIntersections`(75-86): `CircleComponent.lineSegmentIntersections()`
   で **線分 × 円** の交点。戻り値 `Set<Offset>`。
3. `GraphRectangle.getLineIntersections`(100-105):
   `Rectangle.fromRect(bounds).intersections(lineSegment)` で **線分 × 軸平行矩形** の交点。
   戻り値 `Set<Offset>`。

import: `package:flame/components.dart` / `experimental.dart` / `geometry.dart`(2-4 行)。

### 呼び出し側(重要: `intersections.first` 依存)
`lib/src/graph_view/behavior.dart:374-387` `_getLineIntersections`:
- ノード中心同士を結ぶ線分(`GraphLine(source.center, target.center)`)と source 形状の
  交点を取り、**`intersections.first`** を返す(リンク端点 = ノード境界上の接続点)。
- **問題(計画 B1 の受け入れ基準)**: flame の `intersections` は **Set(順不同)**。
  自前実装で `first` が別の点を返すとリンク端点が変わりうる。
  → **`first` 依存を排除し、「線分の始点(= ノード中心から相手側へ向かう向き)に最も近い
    交点を選ぶ」など明示的な選択に変更する**こと。これは [[link-endpoint-gap-followup]]
    (リンク端点のすき間問題)とも接続する。

### 実装方針(推奨)
1. `lib/src/utils/` に幾何ユーティリティを新設(例 `geometry_intersect.dart`)。
   - 線分 × 円: 中心・半径と線分の交点(2 次方程式)。
   - 線分 × 軸平行矩形: 4 辺(線分)との交点を集める、または slab 法。
2. `shape.dart` の 3 箇所を自前関数に差し替え、flame import と `Vector2`/`LineSegment`/
   `CircleComponent`/`Rectangle` を除去。`_vector2SetToOffsetSet` も不要化。
3. `_getLineIntersections` の `intersections.first` を明示的な点選択に変更。
4. `pubspec.yaml` から `flame: ^1.23.0` を削除(17 行付近)。example/pubspec.yaml も確認。

### セーフティネット(必須・先に書く)
- **flame 版と自前版の数値一致テストを先に書く**: 円・矩形について代表的な線分で、
  flame の結果と自前結果が一致(浮動小数許容誤差内)することを確認 → 確認できたら flame 除去。
  - 注: flame 除去後はテストから flame を呼べないので、「並走確認」は flame がある間に行い、
    最終テストは自前版の **既知の期待値**(手計算した交点座標)に対する assert に置き換える。
- golden テストでリンク端点描画が不変であること(既存 golden は環境差で一部失敗するが、
  **flame 撤去前後で失敗集合が増えない**ことを確認。下記「golden の扱い」参照)。

### 受け入れ基準
- `pubspec.yaml` から flame が消え、`grep -rn "package:flame" lib/` が 0 件。
- 交差計算の単体テストが緑(自前版の既知期待値)。
- `intersections.first` 依存を排除(明示的な点選択)。
- `flutter analyze lib/` 新規 error/warning なし、`dart format --set-exit-if-changed` 0。
- 非 golden テスト緑、golden の失敗集合が flame 撤去で増えない。

- このブランチの golden テストは**ベースラインでも数件失敗**する(フォント/レンダリングの
  環境差、0.01〜1.36% のピクセル差)。E1/削除パス/phaseA いずれも「変更を stash しても
  同じ集合が失敗」=無関係、と確認してきた。B1 でも **撤去前後で失敗集合が増えないこと**を
  もって不変と判断する(CI と同一環境での golden 撮り直しは別タスク)。

## 既知の注意点(memory 由来・B1 周辺)
- [[link-endpoint-gap-followup]]: 通常時もリンク両端がノードからわずかに離れる定常オフセット。
  B1 の `intersections.first` 排除と同じ幾何コードに触れるので、**B1 では「挙動を変えない」
  方針を守りつつ、端点選択ロジックを明示化**する(すき間の本格調査は別タスク)。
- shape.dart の公開 API: `GraphCircle`/`GraphRectangle`/`GraphShape` は
  `graph_view.dart` で export 済み。**公開シグネチャ(`getLineIntersections(Rect, GraphLine)
  -> Set<Offset>`)は変えない**こと(後方互換)。
