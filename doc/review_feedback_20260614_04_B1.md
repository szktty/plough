## 論点ごとの所見

### 1. 円交差の正しさ — 問題なし(微小な観察 1 件)

- 2 次方程式・退化分岐・`t∈[-ε,1+ε]` クランプは正しい。
- **厳密接線は 1 点に潰れる**ことを実測で確認した。テストの接線ケース
  (`(0,70)-(200,70)`, center `(100,100)`, r=30)は `discriminant=0.0`、
  `t1==t2==0.5` となり `{t1,t2}` の Set が要素 1 に縮退する
  (`geometry_intersect.dart:50,56,61`)。
- 観察(実害なし): **「ほぼ接線」**(判別式が `0 < disc < 微小正値`、`-ε` 閾値は
  通過する)の場合、`t1` と `t2` がわずかに異なり 2 点返りうる。ただし接続点計算は
  始点(中心)に最も近い点を選ぶため、2 点が近接していても最近傍 1 点に収束し、
  描画上の差は ε 級。**修正不要**。気になるなら将来 `(t2-t1).abs() <= ε` で
  マージする手もあるが現状は過剰。

### 2. 矩形交差(Liang–Barsky)— 問題なし

- `p[i].abs() <= ε`(辺平行)で `q[i] < -ε` のとき棄却、`tEnter>ε`/`tExit<1-ε` の
  境界判定はいずれも正しい(`geometry_intersect.dart:97-124`)。
- 「辺と完全に重なる線分」で自前版が入口・出口 2 点を返す(flame は 3 点)既知差異は、
  **center-to-center リンク経路では始点が矩形内部のため発生しない**。判断は妥当。
  実用上、辺に完全重畳する center-to-center 線分は両ノード中心が同一辺直線上に
  乗る縮退配置でのみ生じ、その場合でも接続点は最近傍 1 点に収束する。

### 3. `first` 排除の等価性 — 問題なし、むしろ改善

- `_getLineIntersections`(`behavior.dart:382-403`)は始点=source.center を渡す。
  source.center は形状内部にあるため、円・矩形いずれも **境界交差は出口側の 1 点のみ**
  (円: t1<0 が除外され t2 のみ / 矩形: `tEnter≈0` で入口を返さず `tExit` のみ)。
  したがって従来 `first` が返していた点と **実質同一**で、複数交差が返る縮退ケースでのみ
  最近傍選択が決定性を担保する純粋な改善。挙動不変の主張は妥当。
- 反例観点: source.center が形状外に出る前提崩れ(ノードの極端な重なり)。この場合は
  円なら入口・出口 2 点が候補になりうるが、最近傍(中心に近い側=入口)を選ぶため
  端点が「飛ぶ」ことはなく、むしろ中心寄りで安定する。`first` 時代より退行しない。
- [[link-endpoint-gap-followup]] のすき間本格調査を B1 で行わず挙動不変に留める線引きは
  妥当。今回触れたのは交差点の **選択ロジック**であり、定常オフセット(すき間)は
  別レイヤ(端点描画側)の話で本コミットでは変わっていない。

### 4. 公開 API 後方互換 — 問題なし

- `GraphLine`/`GraphCircle`/`GraphRectangle`/`GraphShape` の公開シグネチャ不変。
  `getLineIntersections(Rect, GraphLine) -> Set<Offset>` 維持。
- 削除した `flameLineSegment` は `@internal`、`_vector2SetToOffsetSet` は private。
  パッケージ外への影響なし。

### 5. flame 完全撤去 — 問題なし

- `lib/` 実参照 0 件、pubspec.yaml から削除確認。flame は graph 描画専用の重い
  ゲームエンジンで、推移的依存(vector_math 等)も flame 経由でのみ引いていたなら
  併せて整理される。`pubspec.lock` の最終確認は CI / `flutter pub get` 後の
  差分で担保される想定で問題ない。

### 6. スコープ/粒度 — 妥当

- 実装+恒久テストを 1 コミット、パリティテストを撤去と同時削除する判断は合理的。
  flame が消えればパリティテストはコンパイル不能になるため、同一コミットでの削除が正しい。

## 任意フォローアップ(B1 スコープ外・優先度低)

1. **`segmentRectIntersections` の一般 API としての始点境界仕様**: 始点が辺ちょうど上
   (`tEnter≈0`)のとき入口を返さず出口のみになる。center-to-center 用途では始点=
   中心で内部のため無害だが、`GraphRectangle.getLineIntersections` を外部が汎用交差
   API として直接使う場合に直感と異なりうる。doc に「始点が境界/内部のときの戻り」を
   一文補足すると親切(必須ではない)。
2. **接線近傍のマージ**(論点 1 の観察): 必要が生じたら `(t2-t1).abs() <= ε` で 1 点化。
   現状は過剰実装なので不要。

## 結論

B1 はそのままマージ可。幾何計算の境界条件(接線・退化・辺重なり・始点内側)に
見落としはなく、`first` 排除は挙動不変かつ決定的化の正味改善。
